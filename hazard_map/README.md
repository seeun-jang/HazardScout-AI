# 좌표 매핑 (hazard_map)

로봇이 돌아다니면서 **"어디가 막혔는지, 어디에 위험물이 있는지"를 좌표 지도로 만드는** 기능입니다.

- **바코드**: 막힌 길에 붙여두면 로봇이 읽고 지도에 표시한 뒤, 정해둔 방향으로 피합니다.
- **YOLO(Safety7)**: 교통콘, 소화기, 안전모 같은 물체를 찾으면 그 위치를 지도에 올립니다.
- **지도 보기**: 영상 오른쪽 아래 미니맵, `http://192.168.25.112:5001/map` 웹 페이지, `map_state.json` 파일로 확인합니다.

**팀 서버 파일은 하나도 고치지 않습니다.** 팀 서버의 Final 파일들이 원본 서버를 감싸서 기능을 바꾸는 것과 같은 방식으로, 실행할 때만 지도 기능을 붙입니다. 기존 실행 명령을 쓰면 지금과 똑같이 동작합니다.

## 1. 전체 흐름

```
카메라 프레임 (640x480, 약 12FPS)
   │
   ├─ YOLO 스레드 (8프레임마다) ── Safety7 탐지 ── 거리/방향 계산 ── 위험물 지도
   │
   ├─ 바코드 스레드 (3프레임마다) ── 읽으면 → 막힌 칸 표시 + 위치 보정 + 회피
   │
   └─ 카메라 스레드 (매 프레임)
        ├─ 위치 추적: 지금 주행 상태(전진/회전 등) × 흐른 시간
        └─ 미니맵 그리기 → PC/모바일 화면으로 전송

바코드 읽기는 파이에서 한 번에 수십~수백 ms가 걸려서, YOLO처럼 별도 스레드에서 합니다.
이전 프레임을 아직 읽는 중이면 그 프레임은 건너뛰기 때문에 영상이 기다리지 않습니다.

지도 웹 서버 (포트 5001): /map 페이지, /api/map JSON
```

## 2. 좌표계: 바닥을 바둑판으로

장소를 **30cm 칸**으로 나눕니다. 이 크기는 `site_map.json`의 `cell_size_m`으로 바꿀 수 있습니다.

```
      x →  0    1    2    3   ...
  y  0   ┌────┬────┬────┬────┐
  ↓  1   │    │ ■  │    │    │   ■ = 막힌 칸 (1,1)
     2   │    │ 🤖 │    │    │   🤖 = 로봇 (1,2), 북쪽(N)을 보는 중
     3   └────┴────┴────┴────┘
```

| 규칙 | 내용 |
|---|---|
| 원점 | 지도 왼쪽 위 칸이 (0,0) |
| x | 오른쪽(동, E)으로 커짐 |
| y | 아래쪽(남, S)으로 커짐 |
| 칸 좌표 | (x ÷ 칸 크기, y ÷ 칸 크기)의 몫. 0.45m, 1.05m → 칸 (1, 3) |
| 방향 | 나침반 각도. N=0°, E=90°, S=180°, W=270°. 오른쪽으로 돌면 커짐 |

내부에서는 칸이 아니라 **미터 단위**로 위치를 계산하고, 보여줄 때만 칸으로 바꿉니다. 칸보다 작은 움직임도 쌓여서 반영됩니다.

## 3. 로봇은 자기 위치를 어떻게 아나

PiCar-Pro에는 바퀴 회전 센서(엔코더)가 없습니다. 그래서 두 가지를 섞어 씁니다.

### (1) 데드레커닝: 시간으로 어림잡기

서버의 `current_motion`(지금 전진 중인지, 회전 중인지)과 흐른 시간으로 계산합니다.

| 주행 상태 | 위치 | 방향 |
|---|---|---|
| forward | 바라보는 쪽으로 `forward_m_per_sec` × 시간 | 그대로 |
| backward | 반대쪽으로 이동 | 그대로 |
| left / right | `turn_m_per_sec`로 전진하면서 | `yaw_deg_per_sec`만큼 왼쪽/오른쪽으로 돎 |
| backleft | 후진하면서 | 차체는 **오른쪽**(시계 방향)으로 돎 |
| backright | 후진하면서 | 차체는 **왼쪽**으로 돎 |

> 후진할 때 핸들을 왼쪽으로 꺾으면 차 앞부분은 오른쪽으로 돕니다. 자동차 후진 주차와 같아요.

이 방식은 오래 갈수록 오차가 쌓입니다. 그래서 (2)로 바로잡습니다.

### (2) 바코드 보정: 표지판을 보면 위치를 다시 맞춤

바코드는 **어디에 붙어 있는지 미리 알고 있으니까**, 바코드까지의 거리와 각도를 재면 로봇 위치를 거꾸로 계산할 수 있습니다.

```
로봇 위치 = 바코드 위치 − (바코드까지 거리) × (바코드를 보는 방향)
```

- 방향도 바코드에 적어둔 `robot_heading`으로 맞춥니다. 1D 바코드는 라벨 앞면을 대략 마주 봐야 읽히기 때문에, 읽혔다는 것 자체가 그 방향을 보고 있다는 뜻입니다. 시간으로 어림잡은 방향은 수동으로 몇 번 돌면 크게 틀어지므로 바코드 쪽을 믿습니다.
- 카메라(목)를 15° 넘게 옆으로 돌리고 있으면 각도를 믿기 어려워서 보정하지 않습니다.
- 테스트에서 15cm 어긋나 있던 추정 위치가 바코드 한 번에 0.1cm 오차로 맞춰졌습니다.

## 4. 바코드: 막힌 길 + 위치 기준점

### 바코드에는 번호만 넣음

바코드에는 `1100` 같은 **숫자 4자리만** 넣고, 그 번호의 의미는 `site_map.json`에 적습니다.

```json
"1100": {"cell": [1, 1], "robot_heading": "N", "action": "right", "note": "복도 끝 막힘"}
```

> "1100번 바코드는 (1,1) 칸에 붙어 있고, 로봇이 북쪽을 보며 이걸 읽으면 오른쪽으로 피한다"

번호만 넣는 이유:

| 이유 | 설명 |
|---|---|
| 멀리서 읽힘 | Code128은 숫자 2개를 한 글자로 묶습니다. `1100`은 막대 단위 57개, `BLOCK:1,1;N;right`는 222개. 같은 20cm 라벨이면 76cm 대 24cm 거리 차이 |
| 다시 안 뽑아도 됨 | 회피 방향이나 좌표를 바꿀 때 파일만 고치면 됨 |
| 실수를 미리 잡음 | 서버를 켤 때 지도 밖 좌표, 회피했더니 벽인 경우 등을 `[지도 경고]`로 알려줌 |

### 거리 계산

카메라에서 멀수록 작게 보이는 원리(핀홀 카메라)를 씁니다.

```
거리(m) = focal_px × 막대 부분 실제 폭(m) ÷ 화면 속 막대 폭(px)
```

- `focal_px`: 카메라마다 다른 값. [10-1](#10-1-focal_px-카메라-초점-거리)에서 한 번 잽니다.
- 막대 부분 실제 폭: 20cm 라벨이면 14.48cm. `make_barcodes.py`가 알려줍니다.

### 바코드를 읽었을 때

| 거리 | 하는 일 |
|---|---|
| 1.5m 이내 (`max_read_distance_m`) | 막힌 칸 표시 + 위치 보정 |
| 0.6m 이내 (`trigger_distance_m`) | 위의 것 + **회피 동작** (같은 바코드는 8초에 한 번) |

오인식을 막으려고 연속 2번 이상 읽혀야 인정합니다.

## 5. YOLO 위험물을 좌표로 바꾸기

팀의 Safety7 모델(`models/safety7.pt`)이 찾는 7종을 지도에 올립니다.

| 클래스 | 이름 | 기본 높이 | 통행 막음 |
|---|---|---|---|
| traffic_cone | 교통콘 | 0.30m | **예** (경로 찾기에서 피함) |
| fire_extinguisher | 소화기 | 0.40m | 아니오 |
| safety_helmet | 안전모 | 0.15m | 아니오 |
| safety_vest | 안전조끼 | 0.60m | 아니오 |
| safety_gloves | 안전장갑 | 0.22m | 아니오 |
| earmuffs | 귀덮개 | 0.18m | 아니오 |
| safety_goggles | 보안경 | 0.07m | 아니오 |

**높이는 현장에 둘 실물을 재서 `robot_config.json`에 넣어야 합니다.** 거리 계산에 그대로 쓰입니다.

### 계산 순서

```
1) 거리   = focal_px × 실물 높이 ÷ YOLO 박스 높이(px)
2) 방향   = 로봇 방향 + 카메라(목) 좌우 각도 + 화면 속 좌우 각도
             화면 속 좌우 각도 = atan((박스 중심 x − 320) ÷ focal_px)
3) 위치   = 로봇 위치에서 그 방향으로 거리만큼 간 곳
4) 합치기 = 같은 종류가 45cm 안에서 다시 보이면 같은 물체 → 위치 평균
            (가까이서 본 결과에 가중치를 더 줌)
5) 확정   = 3번 이상 보이면 지도에 표시. 확정 전 후보는 6초 안 보이면 지움
```

### 지도에 안 넣는 경우 (오차가 커서)

- 신뢰도 0.45 미만
- 박스가 화면 위/아래 끝에 걸림 (물체가 잘려서 높이를 믿을 수 없음)
- 0.15m보다 가깝거나 3m보다 멂
- **로봇이 회전 중** (방향 추정이 부정확)

YOLO 추론은 0.3~1초 걸리는데, 추론을 **시작하는 순간**의 로봇 위치를 기억해 두고 계산합니다. 로봇이 움직이는 동안의 어긋남을 줄이기 위해서예요.

## 6. 회피 동작

바코드에 정해둔 `action`대로 움직입니다.

| action | 동작 |
|---|---|
| left | 정지 → 0.6초 후진 → 왼쪽 조향으로 90° |
| right | 정지 → 0.6초 후진 → 오른쪽 조향으로 90° |
| back | 정지 → 0.6초 후진 → 후진 왼쪽 조향으로 180° (유턴) |
| stop | 정지만 |
| none | 아무것도 안 함. **위치 보정만 하는 기준점 바코드** (아래 참고) |

**기준점 바코드 (`"action": "none"`)**: 막힌 곳이 아닌 벽이나 기둥에 붙여서, 지나가면서 위치만 다시 맞추는 용도입니다. 갈림길이나 긴 복도 중간에 붙이면 위치 오차가 쌓이지 않습니다. `cell`에는 라벨이 붙은 벽/기둥 칸을 적습니다(지도에 막힘으로 표시하지는 않음).

- **회전 시간은 `90 ÷ yaw_deg_per_sec` 초로 계산합니다.** 그래서 [10-3](#10-3-yaw_deg_per_sec-회전-속도)의 회전 속도 보정이 중요합니다.
- 주행 명령을 0.25초마다 다시 보냅니다. PC 서버에는 "1.2초 동안 명령이 없으면 정지"하는 안전장치가 있는데, 회전에는 1.6초가 걸려서 한 번만 보내면 중간에 멈춥니다.
- 시간은 기다린 횟수가 아니라 **실제 흐른 시간**으로 셉니다. 파이가 바빠서 대기가 길어져도 더 돌지 않습니다.
- **사용자가 방향키나 조이스틱, STOP을 누르면 회피가 바로 중단**되고 사용자 조작을 따릅니다.
- 회피가 끝나면 로봇 방향을 가까운 90° 단위로 정리합니다.
- PiCar-Pro는 앞바퀴 조향식이라 제자리 회전이 안 되고, 도는 동안 앞으로 나아갑니다. 회피 방향 쪽에 1~2칸 공간을 두세요.

## 7. 팀 서버에 붙는 방식

팀 서버(mj 브랜치, 11월 9일 버전)는 이렇게 생겼습니다.

```
GUIServer_custom.py (PC Final)         GUIServer_mobile_final.py (모바일 Final)
   └ 감싸서 기능 변경                       └ 감싸서 기능 변경
GUIServer_custom_base.py (PC 원본)      GUIServer_mobile.py (모바일 원본)
   └ AsyncYOLO: 카메라 루프가 매 프레임 async_yolo.draw(frame) 호출
```

`run_pc_map.py`, `run_mobile_map.py`는 이 위에 한 겹을 더 씌웁니다.

1. 원본 서버의 `AsyncYOLO` 클래스를 지도 기능이 붙은 것으로 바꿔 끼웁니다.
   - `draw()`: YOLO 박스를 그린 다음 위치 추적, 바코드, 미니맵 처리
   - `_run_inference()`: 추론 직전 로봇 위치를 기억해 두고, 결과를 위험물 지도에 반영
2. `AsyncYOLO`가 만들어지는 순간(Final 파일이 `robot_ctrl` 등을 다 바꾼 뒤)에 `robot_ctrl`을 한 번 더 감쌉니다. 사용자 조작이 들어오면 회피를 중단하기 위해서예요.
3. 그다음 Final 파일의 실행 함수(`run()` / `main()`)를 그대로 부릅니다.
4. 종료할 때 바꾼 것을 모두 되돌리고 지도를 저장합니다.

목(카메라) 좌우 각도는 Final 파일의 `neck_controller.position["a_pan"]`에서 읽습니다.

> 실제 팀 서버 코드(mj 브랜치)에 하드웨어만 가짜로 바꿔 끼워서, PC와 모바일 양쪽 모두 위 흐름을 테스트했습니다. 실제 로봇 테스트는 아직입니다.

## 8. 파일 구성

| 파일 | 역할 |
|---|---|
| `site_map.json` | **현장마다 수정.** 격자 크기, 출발 위치, 바코드 |
| `robot_config.json` | **로봇마다 한 번 보정.** 속도, 회전 속도, 카메라, 위험물 높이 |
| `run_pc_map.py` | PC 서버 + 지도 실행 |
| `run_mobile_map.py` | 모바일 서버 + 지도 실행 |
| `pi_check_map.py` | 파이에서 설치 확인, 카메라 보정 |
| `make_barcodes.py` | 인쇄용 바코드 라벨 생성 |
| `test_map.py` | 노트북 시뮬레이션 테스트 |
| `map_config.py` | 설정 읽기, 좌표 변환, 설정 실수 검사 |
| `map_pose.py` | 로봇 위치/방향 추적 |
| `map_barcodes.py` | 바코드 인식, 거리/방향 계산 |
| `map_hazards.py` | YOLO 탐지 → 지도 좌표, 여러 번 본 것 합치기 |
| `map_grid.py` | 격자 지도, 경로 찾기(A*), 지도 그림 |
| `map_avoider.py` | 회피 동작 |
| `map_core.py` | 위 모듈을 하나로 묶음 |
| `map_hooks.py` | 팀 서버에 연결 |
| `map_web.py` | 지도 웹 페이지 (포트 5001) |

## 10. 보정: 로봇마다 한 번

순서대로 하세요. 값은 모두 `robot_config.json`에 넣습니다.

### 10-1. focal_px (카메라 초점 거리)

바코드 거리와 YOLO 거리 계산에 모두 쓰이는 가장 중요한 값입니다.

1. 팀 서버를 끕니다.
2. 라벨을 벽에 붙이고, **카메라 렌즈에서 라벨까지 정확히 50cm**에 로봇을 둡니다. 카메라는 정면을 봅니다.
3. 실행합니다.
   ```bash
   ~/picar-yolo/bin/python pi_check_map.py --calibrate 0.50
   ```
4. 마지막에 나오는 `focal_px = ???` 값을 `camera.focal_px`에 넣습니다.
5. 다시 `--camera`로 실행해서, 줄자로 잰 거리와 출력 거리가 맞는지 확인합니다.

### 10-2. pan_sign (카메라 좌우 방향)

1. `run_pc_map.py`나 `run_mobile_map.py`로 서버를 켭니다.
2. 지도 페이지(`:5001/map`)를 열고, 카메라(목 A)를 **오른쪽**으로 돌립니다.
3. "카메라 좌우" 값이 **+**가 되면 그대로 두고, **-**가 되면 `camera.pan_sign`을 `-1`로 바꿉니다.

### 10-3. yaw_deg_per_sec (회전 속도)

1. 바닥에 로봇 방향을 테이프로 표시합니다.
2. 오른쪽 회전 버튼을 누르고, 정확히 90° 돌 때까지 걸린 시간을 잽니다. 휴대폰 동영상으로 찍으면 정확합니다.
3. `yaw_deg_per_sec` = 90 ÷ 걸린 시간(초). 예: 1.6초 → 56

### 10-4. forward_m_per_sec, turn_m_per_sec (주행 속도)

1. 전진 버튼을 정확히 3초 누르고, 이동한 거리를 줄자로 잽니다.
2. `forward_m_per_sec` = 거리(m) ÷ 3
3. 회전 버튼으로도 3초 돌고, 바퀴가 그린 호의 길이를 대략 재서 `turn_m_per_sec`에 넣습니다. 정확하지 않아도 됩니다.

### 10-5. 위험물 높이

현장에 둘 교통콘, 소화기 등의 실제 높이를 재서 `hazards.classes.<이름>.height_m`에 넣습니다. 그다음 줄자로 거리를 재면서 확인합니다.

```bash
~/picar-yolo/bin/python pi_check_map.py --camera --yolo
```

출력 거리가 실제보다 길면 `height_m`을 줄이고, 짧으면 늘립니다.

## 11. 현장 세팅

1. **기준점 정하기**: 장소의 왼쪽 위 모서리를 (0,0)으로 정하고, 바닥에 30cm 간격으로 대략 표시합니다(테이프 몇 줄이면 충분).
2. **`site_map.json` 작성**
   - `grid_w`, `grid_h`: 장소 가로/세로 칸 수
   - `start_cell`, `start_heading`: 서버를 켤 때 로봇을 놓는 칸과 방향. **매번 같은 곳에 같은 방향으로 놓고 켜세요.** 위치 추적의 출발점입니다.
   - `barcodes`: 막힌 곳마다 번호, 칸, 로봇이 볼 방향, 회피 동작
3. **라벨 만들기**: 노트북에서 `python3 make_barcodes.py`. 출력되는 "막대 부분 폭"이 `robot_config.json`의 `barcode.bar_width_m`과 같은지 확인합니다(다르면 알려줌).
4. **인쇄**: **실제 크기(100%)**, 무광 용지. 20cm 라벨이 A4 가로에 들어갑니다.
5. **부착**: 막힌 칸의 로봇 쪽 면에, **카메라 높이(바닥에서 20~40cm)**로 붙입니다. 로봇이 오는 방향을 정면으로 보게 하세요.
6. **복사**: 수정한 `site_map.json`을 파이의 `~/hazard_map/`에 다시 복사합니다.
7. **확인**: 서버를 켜고 로봇을 바코드 쪽으로 몰아서, 지도에 빨간 칸이 생기고 회피하는지 봅니다.

## 12. 지도 보기와 API

| 주소 | 내용 |
|---|---|
| `http://192.168.25.112:5001/map` | 지도 페이지. 1초마다 갱신. 칸을 누르면 목표 지정 → 막힌 곳을 피한 경로 표시 |
| `GET /api/map` | 지도 데이터 JSON (관제 대시보드용) |
| `GET /map.png` | 지도 그림 |
| `POST /api/map/goal` | `{"cell": [x, y]}` 목표 지정, `{"cell": null}` 해제 |
| `POST /api/map/reset` | 지도 초기화. 로봇을 출발 칸에 다시 놓은 뒤 사용 |

`/api/map` 예시 (일부):

```json

  "grid_w": 12, "grid_h": 8, "cell_size_m": 0.3,
  "robot": {"x": 0.45, "y": 1.05, "heading": 90.0, "heading_name": "E", "cell": [1, 3],
            "motion": "stop", "avoiding": false, "camera_pan": 0.0},

  "hazards": [{"class": "traffic_cone", "name_ko": "교통콘", "cell": [2, 1], "x": 0.75, "y": 0.45,
               "conf": 0.82, "hits": 3, "blocks_path": true}],
  "visited": [[1, 6], [1, 5], [1, 4], [1, 3]],
  "events": [{"time": 1794194348.1, "type": "barcode", "text": "바코드 1100: 칸 (1, 1) 막힘 (복도 끝 막힘)"}],
  "goal": [10, 6], "path": [[1, 3], [2, 3], "..."]

```

영상 위 미니맵의 글자: C 교통콘, F 소화기, H 안전모, V 조끼, G 장갑, E 귀덮개, O 보안경.

## 13. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| `인식 엔진: opencv-qr` | zxing-cpp를 `~/picar-yolo/bin/pip`로 설치했는지 |
| `AsyncYOLO 가 없어 연결할 수 없습니다` | 서버 폴더에 11월 버전 서버 파일(`GUIServer_custom_base.py` / `GUIServer_mobile.py`)이 있는지 |
| `Final 서버 파일이 없어 원본 서버만 실행` | 모바일 Final 파일 이름이 다르면 `--wrapper` 지정 |
| YOLO 초기화 실패 | 지도도 같이 꺼집니다(YOLO 클래스에 붙어 있음). 기존 서버 문제부터 해결 |
| 바코드를 못 읽음 | `pi_check_map.py --camera`로 확인. 조명 반사, 인쇄 크기 100%, 카메라 높이 |
| 바코드 거리가 이상함 | `focal_px` 보정(10-1), `bar_width_m`이 라벨과 같은지 |
| 위험물이 지도에 하나도 안 올라감 | `pi_check_map.py --model`로 모델 클래스가 `robot_config.json`과 맞는지 |
| 회피 때 너무 많이/적게 돎 | `yaw_deg_per_sec` 보정(10-3) |
| 지도에서 로봇이 엉뚱한 곳 | 서버 켤 때 `start_cell`, `start_heading` 대로 놓았는지. 지도 페이지에서 "지도 초기화" |
| 위험물 위치가 좌우 반대 | `pan_sign`(10-2) |
| 위험물 거리가 틀림 | 해당 클래스 `height_m`(10-5) |
| 5001 포트 열기 실패 | `--map-port 5002` |
| 영상이 느려짐 | `robot_config.json`의 `barcode.detect_every_n_frames`를 3 → 5 |

## 14. 한계와 다음 단계

**한계 (솔직하게)**
- 바퀴 센서가 없어서, 바코드를 오래 못 보면 위치 오차가 커집니다. 갈림길이나 긴 복도에 기준점 바코드(`"action": "none"`)를 붙이면 줄어듭니다.
- 위험물 거리는 "실물 높이를 안다"는 가정에 기댑니다. 누워 있거나 일부가 가려진 물체는 거리가 틀립니다.
