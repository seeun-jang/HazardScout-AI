3. 10월 중순~말: 로봇 움직임 끊김 원인 분석 - 본인 직접 수행
======================================================================

[3-1. 문제 인식]
- 카메라·YOLO·OLED·목 서보를 함께 실행할 때 관절이 버벅이거나
  간헐적으로 힘이 약해 보이는 현상을 직접 확인.
- YOLO 추론의 높은 CPU 부하 때문인지, OLED의 I2C 전송 때문인지,
  서보 PWM 제어 호출 비용 때문인지, 기구·전원 문제인지 처음부터 단정하지 않음.
- 하나의 조건을 변경하고 나머지 조건을 유지하는 방식으로 단독/결합 실험 구성.

[3-2. 본인 직접 작성한 테스트·계측 코드]
- 바퀴·목 서보·집게·카메라·YOLO·OLED를 각각 분리 시험하는 스크립트 작성.
- YOLO ON/OFF, OLED ON/OFF, OLED 갱신 주기, PWM 캐시 적용 유무,
  I2C 전송 속도 등 변수별 비교 실험 코드를 직접 작성·수정.
- 평균·최대 PWM 호출 시간, OLED 프레임 전송 시간, 전송 횟수,
  오류 횟수 및 실기 동작을 함께 기록하여 원인 가설을 검증.
- 사용한 채널: PCA9685 0(조향), 1(A 좌우), 2(B 상하), 3(A 상하), 4(집게).
- 정상 동작 중이던 기본 제어 코드와 별도로 실험 파일을 관리해 비교 가능성 유지.

[3-3. 역할 구분]
- 테스트 방법·측정 지표·실험 스크립트 개발 및 원인 분석: 본인.
- PWM 객체 재사용과 OLED 업데이트 구조 개선 알고리즘 개발: 본인.

4. 2026-10-28~10-29: 직접 작성한 단계별 테스트와 최적화 코드

[4-1. 단계별 단독·통합 테스트 코드 - 본인 개발]
- stage1 계열: 바퀴 전진·후진·좌/우회전·후진 좌/우회전 단독 시험.
- stage2_camera_test.py: 카메라 연결, 저해상도 프레임 획득·샘플링 시험.
- stage2_neck_test.py / stage2_gripper_test.py: 목·집게의 단독 구동 시험.
- stage3_yolo_camera_test.py: 팀원이 개발한 YOLO 탐지 기능을 카메라와 연동 시험.
- stage4_oled_test.py / stage4_oled_thread_test.py: OLED 출력·애니메이션 갱신 시험.
- stage5_yolo_oled_test.py: YOLO와 OLED 동시 실행 조건 비교.
- stage6_mobile_no_yolo_test.py: YOLO 제거 조건에서 모바일 서보 동작 비교.
※ 위와 같은 단계별 테스트 파일은 본인이 직접 작성·구성·실행한 코드임.
  테스트에서 호출한 기본 동작·YOLO 탐지 모듈 자체까지 직접 작성한 것은 아님.

[4-2. stage7: 기본 서버 PWM 지연 계측 - 본인 개발/측정]
- 카메라·OLED·음성 실행 / YOLO 추론 OFF 조건에서 호출 시간 수집.
- RPIservo.ServoCtrl.set_angle 호출 시간을 확인하는 계측 코드 직접 작성.
- OLED ON 조건 대표 결과:
  · 목 1 평균 61.7ms / 최대 202.3ms
  · 목 2 평균 83.5ms / 최대 204.7ms
  · 목 3 평균 85.3ms / 최대 205.8ms
  · 집게 평균 약 24ms / 최대 약 201.6ms
- OLED와 서보가 같은 I2C 버스를 공유하는 상황을 주요 지연 후보로 판단.

[4-3. stage8: 목 PWM 객체 재사용 최적화 - 본인 개발]
- 기존 set_angle 호출 때마다 I2C/PCA9685 제어 객체를 생성하는 경로를 분석.
- PCA9685 주소 0x5F, 주파수 50Hz 객체를 한 번 생성해 재사용하도록 최적화 코드 개발.
- 목 채널 1·2·3에 우선 적용하고 집게 4·조향 0은 기존 제어 방식을 유지.
- PWM 캐시 적용 전후 호출 시간과 목 동작의 매끄러움을 직접 비교·검증.
- 평균 지연은 줄었으나 OLED ON에서는 끊김이 일부 남아 다음 테스트로 진행.

[4-4. stage9: OLED OFF 원인 분리 - 본인 시험]
- PWM 캐시를 적용한 상태에서 OLED 전송만 OFF한 비교 실험 구성.
- 목 채널 1·2·3 처리 시간 평균이 약 1.3~1.4ms로 줄어드는 결과 확인.
- YOLO나 하드웨어 전체를 단일 원인으로 단정하기보다 OLED/I2C 통신이
  서보 제어 지연에 영향을 준다는 근거를 확보.

[4-5. stage10: OLED 3FPS 제한 실험 - 본인 작성/검증]
- OLED 갱신 주기를 약 3FPS로 제한하는 시험 조건을 직접 구현·비교.
- 일부 목 채널에서 최대 약 174~179ms 지연과 간헐적 버벅임이 잔존.
- 단순 FPS 제한만으로는 충분한 개선이 어려움을 확인.

[4-6. stage11: OLED 변경 프레임만 전송 - 본인 최적화 코드 개발]
- 이전 프레임과 동일하면 OLED 전체 화면 전송을 건너뛰는 로직 구현.
- 눈동자 방향·깜빡임 등 중요한 상태 변화는 유지하며 중복 송신 제거.
- 10초 단위 통계에서 실제 전송 약 6~10회로 기록됨.
- 100kHz 조건보다 400kHz 조건에서 목 동작이 개선되는 경향 확인.

[4-7. stage12: 서보 우선 OLED 갱신 - 본인 최적화 코드 개발]
- 목·집게 조작 중 OLED의 I2C 화면 전송을 보류하도록 우선순위 로직 구현.
- 서보 동작 종료 뒤 약 0.2초부터 화면 갱신을 재개하고 중복 전송도 생략.
- 400kHz 조건에서 실측한 대표 결과:
  · 목 1(A 좌우): 104명령, 평균 0.6ms, 최대 2.7ms
  · 목 2(B 상하): 96명령, 평균 0.5ms, 최대 2.5ms
  · 목 3(A 상하): 54명령, 평균 0.6ms, 최대 5.1ms
  · 집게 4: 332명령, 평균 6.8ms, 최대 23.7ms
  · 기록된 채널의 명령 오류: 0회
- A 좌우·A 상하·집게가 부드러워졌고 B 상하의 미세 떨림은 일부 잔존함을 확인.

[4-8. stage13: OLED I2C 통신 속도 조정 - 본인 설정/측정]
- OLED 단독 화면 전송 시간 측정 코드를 직접 작성해 전체 프레임 12회 측정.
- 변경 전 OLED 전체 전송 평균: 94.63ms.
- /boot/firmware/config.txt에서 I2C 속도를 400kHz로 변경하고 재부팅:
  · dtparam=i2c_arm=on,i2c_arm_baudrate=400000
  · 설정 변경 전 백업: /boot/firmware/config.txt.before_i2c400k
- 변경 후 OLED 전송 평균 24.80ms(최소 24.68ms / 최대 24.99ms).
- 이전 대비 약 73.8% 감소, 약 3.8배 빠른 프레임 전송 결과 확인.

5) 목 각도 범위 부족 및 방향 불일치
   → 팀원 작성 각도·방향 보정 코드 적용 및 실기 검증.

7) PC 서버·GUI 실행 오류
   → 들여쓰기 및 TigerVNC DISPLAY 관련 실행 문제 점검·조치.
