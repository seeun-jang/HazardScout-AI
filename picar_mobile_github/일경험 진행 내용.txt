1. 담당 역할과 작업 방향
======================================================================

1) PuTTY(SSH)를 이용하여 Raspberry Pi에 접속하고 서버를 관리함.
2) 전달받은 Python 기반 로봇 제어·웹 서버 파일을 지정 경로에 배치하고 실행함.
3) Raspberry Pi 4에서 동작 가능한 Python 가상환경과 AI 패키지 버전을 관리함.
4) 카메라, YOLO, OLED, 바퀴 모터, 서보 목, 집게, 조명 간의 연동을 점검함.
5) 터미널 로그와 단계별 분리 테스트를 이용해 오류·동작 지연의 원인을 추적함.
6) 정상 동작하던 기존 서버를 보존하면서 테스트용 파일로 수정 효과를 검증함.
7) 검증된 설정을 별도의 모바일 최종 서버 파일로 통합하고 실제 로봇에서 확인함.
8) 불필요한 임시 테스트 파일을 정리하고, 재현 가능한 파일·실행 방법을 문서화함.

※ 기존 기록상 주된 담당 업무는 신규 프로그램을 처음부터 작성하는 것보다,
   전달받은 코드의 실제 하드웨어 적용과 실행 환경 구성, 오류 해결, 실기 검증이었음.
   이후 실측 결과에 따라 제어 방식 및 최종 서버 통합 작업에도 참여함.

2. 2026-10-07까지 수행한 초기 작업 (기존 기록 반영)
======================================================================

[2-1. 원격 접속 및 서버 구성]
- PuTTY를 사용해 Raspberry Pi의 Linux 터미널에 SSH 원격 접속.
- 로봇 서버 작업 경로 확인: /home/pi/Adeept_PiCar-Pro/Server
- 모바일 서버 GUIServer_mobile.py와 PC GUI용 GUIServer_custom.py의 용도 구분.
- 모바일 HTTP 서버의 포트 5000 및 같은 Wi-Fi에서의 브라우저 접속 테스트.
- PC GUI는 Tkinter/VNC 연동 방식으로 별도 실행 및 초기 연결 확인.
- 서로 다른 서버가 같은 하드웨어를 중복 제어하지 않도록 실행 방식 구분.

[2-2. Python 및 YOLO 실행 환경]
- YOLO용 별도 Python 가상환경 ~/picar-yolo/ 구성 및 실행기 사용.
- ultralytics, PyTorch, torchvision, NumPy, OpenCV, Picamera2 등 필요 패키지 확인.
- 기본 시스템 Python과 YOLO 가상환경의 패키지 충돌 및 호환성 문제 점검.
- Picamera2/NumPy 간 호환성 문제를 확인하고 테스트 환경 조정.
- Raspberry Pi 4에서 PyTorch 실행 시 'Illegal instruction', EXIT=132 현상 분석.
  · 단순한 서버 실행 명령어 오류가 아니라 CPU/빌드 호환성과 관련된 문제로 파악.
  · torch 2.2.1 / torchvision 0.17.1 조합으로 환경을 맞춘 뒤 재검증.
  · CUDA=False의 CPU 추론 환경에서 YOLO 모델 로드 및 추론 성공(EXIT=0) 확인.
- 초기에 yolov8n.pt 모델을 사용하여 80개 클래스 로드·추론 확인.

[2-3. 영상·OLED·주행]
- PiCamera2/libcamera 기반 카메라 연결과 실시간 프레임 획득 확인.
- 모바일 웹 화면에서 카메라 영상과 YOLO 객체 탐지 상자·이름 표시 확인.
- OLED SSD1306의 I2C-1 연결과 주소 0x3C 확인.
- 카메라·YOLO·OLED를 서버와 함께 실행하는 통합 환경 점검.
- 전진·후진·좌회전·우회전·후진 좌우회전 주행 명령 확인.
- 집게 및 목 서보 동작 확인, 조명 제어 기능 점검.

[2-4. 전원 관련 초기 문제]
- 일부 주행 테스트에서 일정 시간이 지나면 Raspberry Pi가 꺼지는 현상 관찰.
  · PWR LED 소등 → PuTTY 연결 종료 → 카메라·서버 종료 순으로 증상이 나타남.
- vcgencmd get_throttled, 터미널 종료 상태, 배터리·모터·서보 부하를 확인.
- 이후 테스트에서 get_throttled=0x0 등 기록을 확인했지만,
  초기 전원 종료 문제의 모든 조건과 원인이 완전히 해결되었다고 단정하지 않음.
- 예비 보호회로 배터리 조합에서 조기 종료 사례가 있었으므로 배터리 호환성도 주의.

  OLED 연결/눈동자 애니메이션/전송 흐름 점검.

  YOLO와 OLED를 함께 실행하는 조건 비교.

  모바일 서버에서 YOLO를 제외한 조건의 서보 동작 비교.
  ※ 단계별 실험의 목적과 파일명에 따른 기능을 기록한 것이며,
     모든 초기 단계의 정량 지표가 보존된 것은 아님.

[4-2. stage7: 실제 모바일 서버 PWM 지연 계측]
- 카메라, OLED, 음성 실행 / YOLO 추론 OFF 상태에서 5초 간격 측정.
- RPIservo.ServoCtrl.set_angle 호출 시간을 기록하는 방식 사용.
- OLED가 켜진 기존 방식에서 관측된 대표 결과:
  · 목 1번 평균 약 61.7ms, 최대 약 202.3ms
  · 목 2번 평균 약 83.5ms, 최대 약 204.7ms
  · 목 3번 평균 약 85.3ms, 최대 약 205.8ms
  · 집게 평균 약 24ms, 최대 약 201.6ms
- OLED와 서보가 같은 I2C 버스를 사용하면서 지연이 발생할 가능성을 확인.

[4-3. stage8: 목 PWM 객체 재사용]
- 기존 set_angle 호출마다 I2C/PCA9685 제어 객체를 다시 생성하는 경로를 분석.
- PCA9685 주소 0x5F, 주파수 50Hz의 제어 객체를 1회 생성해 유지.
- 목 채널 1·2·3에 한정하여 재사용하고 집게 4·조향 0은 기존 방식 유지.
- 이전보다 평균 지연은 줄어들었지만 OLED ON 상태에서는
  여전히 일부 지연 및 움직임 끊김이 남아 추가 비교 필요 확인.

[4-4. stage9: OLED OFF 비교]
- PWM 캐시는 유지하고 OLED 전송만 비활성화해 비교.
- 목 1·2·3번 평균 처리 시간이 대체로 약 1.3~1.4ms 수준으로 감소.
- 목 움직임이 크게 부드러워져 OLED 전송 영향이 중요한 단서임을 확인.

[4-5. stage10: OLED 3FPS 제한 실험]
- OLED를 단순히 약 3FPS로 제한해 OLED/서보 동시 동작 비교.
- 일부 목 채널의 최대 지연이 약 174~179ms 수준으로 남았고
  간헐적인 버벅임·힘 저하가 관찰되어 이 방식만으로는 불충분하다고 판단.

[4-6. stage11: OLED 변경 화면만 전송]
- OLED 눈동자·깜빡임을 유지하면서 동일 화면 프레임 전송 생략.
- 중요 상태(눈동자 방향·깜빡임) 갱신 및 미세 애니메이션 주기 적용.
- 10초 단위 통계에서 실제 전송은 약 6~10회, 중복 프레임은 다수 생략.
- 100kHz 조건보다 400kHz 조건에서 목 움직임이 더 개선됨.

[4-7. stage12: 서보 우선 OLED 갱신]
- 서보 조작 중 OLED 통신을 보류하고, 동작이 종료된 뒤 약 0.2초 후 갱신.
- 화면 변화 없는 경우에도 중복 전송을 생략하도록 유지.
- OLED 눈동자·깜빡임 표시를 유지하면서 서보 우선순위 확보.
- 400kHz 조건의 최종 관찰 기록:
  · 목 1(A 좌우): 104명령, 평균 0.6ms, 최대 2.7ms
  · 목 2(B 상하): 96명령, 평균 0.5ms, 최대 2.5ms
  · 목 3(A 상하): 54명령, 평균 0.6ms, 최대 5.1ms
  · 집게 4: 332명령, 평균 6.8ms, 최대 23.7ms
  · 명령 오류는 기록된 채널에서 0회.
- 실제 체감: A 좌우·A 상하·집게 매끄러움, B 상하 미세한 떨림 잔존.

[4-8. stage13: OLED I2C 단독 전송 시간 측정 및 버스 속도 조정]
- YOLO/모터/서보 등을 끄고 OLED의 단독 전체 프레임 전송 시간을 12회 측정.
- 변경 전(기존 I2C 통신 속도): 평균 94.63ms.
- /boot/firmware/config.txt의 I2C 설정을 400kHz로 변경하고 재부팅.
  · dtparam=i2c_arm=on,i2c_arm_baudrate=400000
  · 설정 변경 전 백업 파일: /boot/firmware/config.txt.before_i2c400k
- 변경 후 OLED 평균 전송 24.80ms(최소 24.68ms, 최대 24.99ms).
- 기존 대비 약 73.8% 감소, 약 3.8배 빠른 전체 프레임 전송을 실측.
- OLED 표시가 정상인지, 서보가 함께 작동할 때 지연이 개선되는지 추가 확인.

[4-9. stage14: YOLO ON 실제 모바일 통합 테스트]
- 12단계의 서보 우선 OLED 방식과 목 PWM 캐시를 유지하며 YOLO 추론 ON.
- 학습 모델 models/hazard_3class_v1.pt 로드, 학습 클래스 3개 확인.
- 카메라 640x480, 설정 목표 12FPS / YOLO imgsz 224, 8프레임 주기.
- 실제 추론 로그 확인:
  · 첫 추론 4720.3ms(초기화 영향 포함)
  · 이후 대표 추론 319.4ms, 247.9ms, 258.7ms.
- 소화기 사진을 카메라에 보여 주어 모바일 영상에서 정상 인식 확인.
- 인식 작업이 진행되는 동안 목·집게를 실제로 조작하여 동시 작동 확인.
- A 좌우, A 상하, 집게는 매끄러움; B 상하는 아주 약한 버벅임.
- 초기 stage14 로그는 목/집게 PWM 계측값을 충분히 담지 않아
  YOLO ON 동시 동작의 채널별 수치가 모두 검증된 것으로 적지 않음.

[5-1. 실행 파일 통합]

- 최종 파일은 기존 모바일 서버의 HTTP/UI/카메라/주행/YOLO 기능을 불러와

- 이전 stage7~stage14 테스트 파일 없이 최종 실행본만으로 시작 가능하도록 구성.

[5-2. 최종 목 서보 범위와 방향]
- A 목 좌우(a_pan): 조이스틱 방향과 실제 이동 방향이 반대인 현상 확인 후 보정.
- A 목 좌우 이동 범위를 초기 ±12도에서 최종 -25~+25도까지 확장.
- A 목 상하(a_tilt)는 기존 ±12도 유지.
- B 목 상하(b_tilt)는 위쪽 +12도 유지, 아래쪽 -20도까지 확장.
- 각도는 '초기 기준 위치에서의 상대 이동각'이며 절대 서보 위치가 아님.
- 목 관절 이외의 집게·조향 제어 및 기본 서보 이동 단계/속도 유지.
- 실기에서 확장된 범위와 방향을 확인하고 현재 범위로 확정.

[5-3. 최종 기능 동작]
- 모바일 웹 접속: HTTP 포트 5000, 같은 Wi-Fi의 브라우저로 원격 제어.
- 카메라: 실시간 영상 출력 정상.
- YOLO: 학습 모델의 소화기 사진 인식 정상.
- OLED: 눈동자 방향·깜빡임 등 애니메이션 정상.
- 목 A 좌우: 최종 방향 및 확대 각도 정상, 부드러운 움직임.
- 목 A 상하: 부드러운 움직임.
- 목 B 상하: 원하는 방향·각도로 이동, 미세한 떨림이 약하게 남음.
- 집게: 잡기/놓기 동작 매끄러움.
- 앞바퀴 조향·주행 및 조명: 기존 모바일 기능 유지.
- 최종 서버의 기본 기능은 실기 작동을 확인했으나,
  장기간 무중단 운용과 음성 최종 명령 성공까지 검증했다는 뜻은 아님.

[5-4. 모바일 서버 핵심 설정]
- PWM 장치: PCA9685 / I2C 1 / 주소 0x5F / 50Hz.
- OLED: SSD1306 / I2C 1 / 주소 0x3C.
- 부팅 I2C: 400kHz(400000 baud).
- 목 PWM 캐시: 채널 1·2·3.
- 집게 채널: 4 / 조향 채널: 0(원래 출력 방식 유지).
- OLED 검사 주기: 약 0.08초.
- OLED 화면 변화가 없으면 전송 생략, 미세 애니메이션 갱신은 약 0.5초 예산.
- 서보 동작 중 OLED 전송 보류, 서보 멈춘 뒤 약 0.2초 후 갱신.
- YOLO 모델: models/hazard_3class_v1.pt (3개 클래스).
- 카메라: 640x480 / 목표 12FPS; YOLO imgsz=224, 8프레임 간격 설정.

7. 실행 중 확인한 로그·이슈·해결 현황

[해결 및 안정화]
1) PyTorch Illegal instruction(EXIT=132)
   -> torch/torchvision 호환 가능한 버전으로 변경 후 YOLO CPU 추론 성공.
2) NumPy/Picamera2 등 패키지 호환 문제
   -> 시스템·가상환경 패키지 및 의존성 확인/조정.
3) OLED 사용 중 목 서보 지연
   -> PWM 객체 재사용 + OLED 중복 전송 생략 + 서보 우선 전송 + I2C 400kHz.
4) A 목 좌우 조작 방향 반대
   -> A 좌우 부호 반전 보정, 최종 실기 확인.
5) 목 관절 이동 범위 부족
   -> A 좌우 ±25도, B 아래 -20도까지 단계적으로 확장 후 확인.
6) YOLO 탐지 화면 정상인데 해당 로그가 안 보임
   -> 초기 14단계는 특정 추론 횟수에서만 로그 출력하도록 되어 있었음.
      최종 실행본에는 인식 결과가 있을 때 간격을 두고 출력하는 로그 적용.

[오류로 확정하지 않은 사례]
- ConnectionResetError [Errno 104]: 사용자가 브라우저를 새로고침할 때 발생한 연결 종료 로그.
  서버 전체가 비정상 종료된 사례로 판단하지 않음.
- '[Voice] ReSpeaker Lite 입력 장치가 없습니다': 음성 기능 조작 과정의 로그.
  실제 마이크 연결·인식은 추후 다시 점검하기로 함.
- Ctrl+C 종료 뒤 추가 Ctrl+C로 발생한 KeyboardInterrupt 메시지:
  정상 종료 완료 뒤 입력이 반복된 상황으로 확인.

[남은 점검]
